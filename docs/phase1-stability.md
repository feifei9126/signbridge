# 第一阶段：输入与播放稳定性

## 范围与备份

本轮先处理反复启停、字幕覆盖和旧会话消息问题，不替换虚拟人，不调整骨骼、手势参数、默认缩放位置或鼠标交互速度，也不增加词条数量。

修改前已在本地仓库外保存 `phase1-20260920-095456/project.tar.gz`，配套保存 SHA-256、Git 基准和工作区补丁。备份不包含 `node_modules`，也不会将本地备份上传到仓库。恢复前应另存后续改动，不要直接覆盖尚未备份的工作。

## 解决的问题

| 场景                                     | 本轮处理                                                 | 仍需注意                                                   |
| ---------------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------- |
| 关闭浮窗后收到迟到转写                   | 关闭先清活动状态；文本必须匹配当前音频会话，不能触发重开 | 主动启动翻译、声音识别或手动预览仍可打开浮窗               |
| 启动尚未完成就点击停止或重开             | 浮窗加载、Worker 启动、音频采集分别校验代次与会话身份    | 本地模型下载或推理不一定能立即中断，但旧结果不会发到新会话 |
| 连续字幕不断打断动作                     | 保留当前段，最多排队 2 段；超过 6 秒的待播段过期         | 队满丢最旧待播段，优先低延迟，不保证全文播放               |
| 拖动视频进度后还在播放旧队列             | 清动作队列与字幕去重状态                                 | 尚未对 ASR 分片实现时间戳级跳转失效                        |
| 未知英文被拆成短别名，中文词内部被删虚词 | 按完整分词匹配别名，匹配后跳过独立虚词                   | 分词仍不等于理解整句意思                                   |
| 未知词或过长文本难以诊断                 | 返回未知词、跳过虚词、截断与剩余文本信息                 | 词库和语义质量需要独立验收                                 |
| 声音与翻译开关状态不同步                 | 声音启动同步翻译状态；翻译停止同步声音按钮               | 真实浏览器权限与服务可用性仍可能导致启动失败               |

## 已执行的验证

2026 年 9 月 20 日本地验证结果：

- `npm run verify` 通过：构建、ESLint、75 项自动化测试、Prettier 检查。
- 在独立临时 Chromium 配置中加载本轮构建的 `dist/`，使用本地测试页面、真实 Three.js 渲染和 GLB 模型；不复用用户浏览器登录和密钥。
- 浏览器冒烟通过 7 项检查：单浮窗与模型加载、手动预览进入动作运行时、浮窗拖动、关闭后迟到转写不重开、显式重新启动、DOM 字幕与视频跳转重置、停止后不再处理字幕变化。
- 浏览器页面和控制台错误列表为空。截图用于检查模型可见性，不作为手语语义正确的证明。

自动化回归测试覆盖启动/停止竞态、旧会话结果过滤、延迟媒体授权后的资源释放、云端请求取消、字幕队列容量与过期、重复字幕、全部 172 个现有别名独立输入的匹配，以及误匹配反例。

### 尚未验证或尚未完成

- 本轮没有调用收费云端 ASR，也没有完整运行真实 Whisper 模型转写；音频生命周期测试使用依赖边界模拟，不能替代端到端识别质量测试。
- 本地浏览器测试不代表所有视频网站的真实字幕结构、权限策略或连续长时间播放都已验证。
- 没有修改词典中的动作数值，没有重新验证手语朝向、动作含义及自然度，不能声称全部动作准确。
- 姿势编辑器、录制器和浮窗的动作数据闭环尚未统一，不在本轮验收范围。
- 没有进行全量依赖安全升级；测试通过不能证明不存在其他缺陷或安全风险。

## 开发者复测

在仓库根目录执行：

```bash
cd signbridge
npm run verify
```

浏览器脚本不包含在上述命令内。需要准备 Playwright 模块及支持加载扩展的 Chromium/Chrome for Testing；这些不是插件运行依赖。本轮不往项目中额外安装它们。

若环境已能解析 `playwright`，且已准备相应浏览器：

```bash
node tests/browser-phase1.mjs
```

也可指定独立运行环境，替换下面两处路径为本机实际位置：

```bash
SIGNBRIDGE_PLAYWRIGHT_MODULE="/absolute/path/to/playwright/index.mjs" \
SIGNBRIDGE_CHROMIUM_PATH="/absolute/path/to/chromium-executable" \
node tests/browser-phase1.mjs
```

脚本使用临时浏览器配置和本地服务器，完成后关闭并清理。报告与截图写入 `signbridge/test-results/phase1-browser/`，该目录不提交 Git。

## 用户复测

1. 在 `chrome://extensions` 确认加载的是本项目最新构建的 `signbridge/dist/`，点击重新加载，再刷新原视频页面；避免同时启用旧目录中的另一份插件。
2. 输入“你好”，检查模型可见且动作能播放；再用 CC 字幕测试连续输入。
3. 开启声音识别后关闭浮窗，等待一段时间，检查浮窗不会被迟到转写重新打开。再次启动应由自己点击控制面板完成。
4. 停止翻译后，字幕继续变化时不应触发新动作；重新启动后应恢复。
5. 拖动视频进度条，确认旧动作被停止；这一步仅验证动作队列重置，不代表 ASR 音频时间线已严格同步。
6. 如遇异常，记录输入文本、操作顺序，以及 `[SB] Translation coverage:` 中的 `matches`、`unmatched`、`truncated`、`remainingText`。公开日志前删除私人字幕和转写内容。

## 后续顺序

先以稳定输入和播放为基线，再统一编辑器、录制器、运行时的数据格式与模型标识；随后建立经手语使用者或专业人员验收的小规模动作集和方向回归。扩大词典数量应放在动作质量验收之后，避免只增加“会动但含义不准”的条目。
