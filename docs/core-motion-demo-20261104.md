# 核心动作、统一来源和简单句演示（2026-11-04）

本轮实施三步：从151段修复候选中建立小型原片对齐集合；默认展示只使用该集合并明确缺词；用固定中文对照测试和实际浏览器验收有限角色表达。

## 1. 原片支持的17个候选单元

交付目录：`/Users/mac/Desktop/手语/SignBridge-核心动作演示-20261104-v1/`。

核心候选：**我、你、家、医院、工作、健康、放松、衣服、裤子、鞋、身体、鼻子、饮料、没有、香蕉、梨、开车**。合计17种中文来源标签、835帧，不等于17个已经语言学批准的中国手语词条。

先对24种目标标签的28个变体准备515张原片抽样图，用本机Vision OCR提取字幕和标题，再由助手查看实际原片接触表、选取示范区间。OCR不把底部导航菜单的词串当作单词证据，也不把字幕直接当作词界。每个核心单元保留原片帧区间、完整名义来源窗口、修复父资源SHA256、原片SHA256、原始容器来源、OCR观测和候选边界说明。

实际发现：

- 原“家/医院/开车”等候选包含前词尾部或教学分解。核心区间排除这些部分，保留一次相对连贯示范。
- 两个“谢谢”候选包含“好啊/谢谢/不客气”的整句示范，暂不切成已知词动作；仍留在研究集合，未删除。
- “帮助”的原片明确讲解朝向谁的方向变化，当前没有可靠的施事/受事方向对齐，因此不把同一条动作反复用于“我帮你/你帮我”。
- 原“眼睛”短片可能在动作完成前截断，“草莓”包含词内教学步骤，“时间”为讲课窗口；这些不进入第一轮核心集合。

核心轨迹是现有修复四元数轨迹的**精确连续行切片**，不新生成、不补帧、不修改原始NPZ。不重命名中文标签，不从整句制造单字，不把相同标签当作同义动作。ID采用 `native_core_<key>_v1`，保留原 `native_fit_*` ID和准确一基帧号列表。

`core-library-v3/core-manifest.json` 绑定核心集合与整个显示索引；`core-alignment.json` 和 `core-evidence/<key>/alignment.json` 记录依据；`coverage-ledger.json` 精确覆盖原151段，17个父片段被选为来源，其余134段仍是研究候选。原1,853+105+3段待审集合不重跑、不改动。

源时间写为“原名义窗口 + 已解码父片段帧号/fps”，没有冒称重测原视频PTS；本轮重新核对了父片段和派生资源的字节哈希，没有冒称重算每个大原视频的全文件SHA256。所有这些限制写入对齐记录。

17条原片/真实Godette完整对照视频及接触表位于 `source-avatar-comparison-v1/`；逐帧渲染835帧，原片/人物帧数相同。对切片重新检查有限单位旋转、真实手部蒙皮/躯干和手臂风险代理、帧间25%/50%/75%以及首尾REST桥接。`core-geometry-check.json` 未触发所测几何风险。自动代理和助手看图均不构成人工语言批准，也不能证明精确无网格穿插。

## 2. 统一展示路径与缺词行为

有核心manifest的本地包默认进入**核心演示**，正常输入只使用17个核心单元。每个单元可打开对应原片和来源记录。核心manifest、父轨迹、帧范围或资源校验失败会禁播，不能悄悄切到旧库。

151条完整修复候选、83条历史拟合、T08和内置词库仍放在研究对照中，来源分别显示。进入研究模式显示范围提示；收起研究详情回到核心模式。核心的原始资源与151条父轨迹同时随本地包保存，但核心规划器只读取核心单元ID；168个文件条目不被宣传为168个独立词。

“他/她/我们/你们/去/来/今天/明天”等无核心动作时明确列出缺口，保留整句、禁播，不使用内置词典补齐。旧研究拟合仍可手动对照，未授予本轮新的批准。输入编辑会停止上一播放，避免新句被拒绝时旧动作继续造成误解。

构建仅在显式 `local-research` 配置及输入manifest下读取核心资料，所有原片证据、轨迹、manifest受逐文件哈希约束。默认公开构建只写 `core-manifest.json={unavailable:true}`，不自动发现本地新动作。本轮不推送GitHub。

## 3. 有限语句与独立拒绝检查

`core-plan.js` 是有限中文规则解析，不是训练得到的手语理解模型：

- 可演示：`我工作/你工作`、`我健康/你健康`、`我放松/你放松`、`我开车/你开车`，以及 `我没有家/你没有饮料/我没有衣服` 等明确缺少对象的表达。
- 角色草案区分施事、谓词、受事、目标、时间、否定。`我帮你/你帮我` 的角色互换可以解析，但因方向动作未核准禁播，既不回退，也不冒称动作方向正确。
- “没有”只作为本轮缺少/不存在对象的候选，不替代“不”；“我没有工作”可能涉及事件否定或没有职业，保留歧义并拒绝组合。
- 复杂否定/情态、疑问、多分句、未知尾句和超过长度的输入不被吞掉；保留原句并阻止“只播认识的部分”。

固定开发对照集 `tests/fixtures/core-sentence-v1.json` 加核心单元测试共72例：37例预期可播放、35例预期拒绝。`sentence-evaluation-v2.json` 为72/72契约通过，错误接受0、错误拒绝0。测试是助手编写的合成中文受限契约，不是独立泛化测试，更不是中国手语翻译或识别准确率。

所有核心候选保持 `human_approved=false`、`semantics_approved=false`、`boundaries_approved=false`、`text_verified=""`、`training_ready=false`、`model_training_ready=false`。本轮未使用GPU、训练模型或修改检查点。
