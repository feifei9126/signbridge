# 第五阶段：动作可视化验收与截图回归

## 目标与边界

本轮将“每次修改后凭记忆看动作”改为可重复的检查流程：选择动作 → 完整回放 → 固定三视图截图 → 人工确认基准 → 下次对照。使用当前真实模型和共享骨骼/播放器，不重新标定手掌、手指、肘部或 REST，不调整浮窗大小与鼠标控制。

**视觉基准不是手语正确性认证。** 保存基准不会修改动作、启用草稿或授予翻译资格；仍需手语使用者核验含义、手形、朝向、位置和节奏。

| 验收条件         | 可观察行为                                                | 验证方法                       |
| ---------------- | --------------------------------------------------------- | ------------------------------ |
| 独立入口         | 控制面板打开“动作验收”，不在浮窗增加按钮                  | 真实扩展页面点击               |
| 复用真实数据     | 读取当前 GLB、52 个内置 SIGNS 和兼容的已保存自定义动作    | 模型哈希、目录与帧数据检查     |
| 不偷偷改动作     | 回放、截图、保存/删除基准不写共享动作库或翻译配置         | 操作前后逐项比较存储           |
| 可重复截图       | 固定正面、人物右侧、人物左侧，包含首尾关键帧              | PNG 尺寸、像素与采样测试       |
| 基准保护         | 保存/替换/删除需确认；不同模型/环境或动作不可混作同一基准 | 重载、跨页、变化与过期结果测试 |
| 故障可恢复       | 取消任务、加载失败和重试有明确状态                        | 浏览器故障注入与取消测试       |
| 不回退已验收功能 | 前四轮浏览器检查仍通过，受保护文件与备份一致              | 自动化回归及逐字节比较         |

## 打开与使用

1. 在 `chrome://extensions` 重新加载当前 `signbridge/dist/` 扩展，关闭旧控制面板后重新打开。
2. 点击 **动作验收**。页面为该扩展下的 `tools/motion-review.html`，请从面板进入，不要双击本地 HTML，也不要切到另一个扩展 ID。
3. 勾选动作，先点 **依次回放全部帧**，观察完整过程。可在回放前选择固定视角；每个动作开始前恢复 REST。
4. 点 **生成关键帧三视图**。从手掌、手指到手肘逐行检查；与旧基准并排查看后，才考虑保存或替换。
5. 下载 PNG 和 JSON 报告作为问题反馈或代码审查附件。基准删除只删除截图参考，不删除动作。

搜索仅隐藏不匹配的行，**不会取消隐藏行的勾选**。选中数量始终显示；每批最多 8 个动作，超过上限需先取消部分勾选。

### 哪些动作出现在列表里

- 内置目录读取 52 个唯一 `SIGNS`，不是 172 个文字查找别名，不包含 `CHARS` 单字回退。
- 自定义目录读取同一扩展、同一浏览器配置中兼容当前模型的已保存动作，包括草稿。未保存的编辑器姿势不在列表里。
- 页面分别显示内置、草稿和已启用状态；内置条目明确标注待人工核验。出现无效库记录时显示数量，不静默删除原记录。
- 骨骼缺失、非有限角度、非法时长或绑定不兼容时拒绝该动作，不用默认角度代替。一个动作校验失败不代表其它条目已验收。

### 怎样读截图

- 每行是一个采样关键帧，列顺序固定为 **正面 / 人物右侧 / 人物左侧**，不是观众的左右。
- 单格 320 × 360 像素，整图宽 960 像素。每个动作最多抽取 12 帧，固定包含首帧和末帧。
- 页面列出原始帧数、采样帧号、未采样数量、总时长和使用骨骼数。页面帧号从 1 开始；JSON 的 `indices` 从 0 开始。
- 截图直接应用每个目标姿态，不调整原角度。完整回放走共享播放器，能看到关键帧之间的运动；截图本身不覆盖全部插值过程。
- 这里的固定视角不能用于修改浮窗相机、模型尺寸或位置。截图完成后恢复正面和 REST。

## 视觉基准与变化提示

第一次截图没有基准。人工核验后可以保存；再次保存会要求确认替换。刷新页面后基准仍在，但截图结果需重新生成。

比对依据包括：

- GLB 实际字节的 SHA-256（包含模型文件内的蒙皮、材质等数据）。
- 当前骨骼/REST 绑定、Three.js 版本、渲染协议、固定视角与尺寸、相机参数。
- 浏览器 User-Agent 和可读取的 WebGL renderer/vendor。环境信息会包含在下载报告里。
- 动作完整规范化数据的 SHA-256，保留原始角度与时长精度，不取整。

模型或渲染环境变化时标为不可直接比较；动作数据变化时提示重新人工复核。两者均保留旧参考图，不自动覆盖、不把新图标为通过。相同环境与动作才计算像素差异：任一 RGB 通道差超过 16 的像素计入变化比例，同时显示 RGB 平均绝对差。

**差异为零只表示本次采样画面一致；差异非零也可能是渲染差异。** 当前不设自动通过阈值，不进行碰撞检测，不证明动作自然或含义正确；也不覆盖整句字幕编排、ASR 效果或所有不同模型的重定向。

动作库变化会取消正在进行的验收并作废旧结果。保存基准前重新检查动作内容；跨页面修改基准时通过事务内版本令牌拦截过期覆盖。

## 存储、导出与清理

- 视觉基准单独存放在当前扩展的 IndexedDB `signbridge-visual-review` 中，不写共享动作库；最多 100 条，PNG 合计不超过 64 MiB，同时受浏览器配额限制。
- 容量不足或存储不可用时显示错误，不自动删除其它基准。可显式删除不需要的参考图；清除扩展数据或卸载扩展会丢失这些基准。
- 第四阶段的动作包仅备份动作数据，**不包含视觉基准**。PNG 和 JSON 可以下载归档，但当前没有视觉基准批量备份/重新导入功能；下载不能等同于可一键恢复。
- JSON 包含动作 ID/名称、帧统计、哈希、渲染环境和对比结果，不导出 ASR 密钥、原字幕或全量浏览器存储；分享前仍应检查自己命名的动作是否涉及隐私。
- 此工具不请求外网、不增加扩展权限；测试中未观察到外部 HTTP 请求。它不控制同时运行的翻译/声音识别页面。
- 空闲时不保持渲染循环；取消、重载或离页时停止播放、清理监听、计时器、Blob URL 和模型/渲染器资源。模型加载超过 20 秒会报错，可停止或重试。

## 验证方法

在内层 `signbridge/` 执行：

```bash
npm run verify
```

浏览器检查是独立脚本，不包含在上述命令内。使用已安装的 Playwright 和支持扩展加载的 Chromium；可用 `SIGNBRIDGE_PLAYWRIGHT_MODULE` 指定 Playwright 模块绝对路径，用 `SIGNBRIDGE_CHROMIUM_PATH` 指定浏览器可执行文件：

```bash
node tests/browser-phase1.mjs
node tests/browser-phase2.mjs
node tests/browser-phase3.mjs
node tests/browser-phase4.mjs
node tests/browser-phase5.mjs
```

这些脚本使用临时浏览器配置，结束后删除，不操作用户日常 Chrome 数据。第五轮会真实加载 GLB，生成截图，验证基准确认/取消/持久化/并发覆盖保护、环境与动作变化、草稿安全、批量限制以及加载故障重试。测试证据输出至忽略提交的 `signbridge/test-results/phase5-browser/`。
