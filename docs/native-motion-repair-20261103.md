# 2026-11-03：人物抖动及交叉修正

本轮针对用户实际观察到的上一展示版154段抖动/肢体交叉问题。上一轮“技术通过”只是可播放和宽松数值代理，不是视觉质量验收。本轮保留全部旧包、原始视频、原始NPZ和待审集合，重新检查来源与真实皮肤模型。

## 已证实的根因

1. 旧映射按源关节旋转逐骨骼驱动人物，没有补偿SMPL-X真人与Godette的肩宽/臂长比例。例如“龟”的双手最近距离从源模型约6.15cm变成目标人物约1.77cm；部分帧源前臂间距14.1cm，目标约3.64cm。旋转符合有限值/单位四元数并不代表空间位置正确。
2. 旧55/10ms方案在25fps时对手指几乎未作平滑，保护了噪声。上一库手指旋转中点残差P95中位约6.53°、最大尖峰近29.98°，可见颤动仍被允许。
3. 原检测只用腕部聚合P95和8mm骨骼中心线阈值，忽略真实手部皮肤、手与对侧前臂、少数尖峰及帧间过渡。旧154段有62段触发本轮更完整的接触/穿插风险代理。

证据在交付目录的 `initial-target-audit.json`、`baseline-skin-samples.json`、`repaired-library-v3/report.json`，包括确切片段ID、帧号、旧/新测量和保留/隔离原因。

## 实施的修正

`src/demo/native-retarget.js` 用源骨骼正向运动学恢复手腕和肘部空间位置，按目标/源臂长比映射到同一肩部中心，再用解析双骨骼IK求人物的上臂/前臂。手掌朝向仍取原始旋转，手指仍来自原始拟合，目标骨骼长度不变。原T08及83条历史动作的旧映射路径不修改。

`src/demo/motion-repair.js` 对所有映射关节作离线测地四元数均值：固定100/60ms或120/80ms（手臂/手指）两个方案。包含噪声端点，不把它们强行保持为未处理值；源文件和源数组均不改动。改变后的显示端点只用于显示派生，不被伪装成原始采集参数。

运动幅度采用同口径100ms低频轨迹的P5..P95包络比较，避免把孤立噪声尖峰当作必须保留的动作范围；原始极值范围仍完整报告。活动腕至少保留85%包络，低于5cm的低活动腕允许最多1cm包络减少，整段旋转偏差P95不超过12°。这是Demo显示修正的明确取舍，不是中国手语准确率。

`src/tools/motion-skin-model.mjs` 直接读取原GLB的真实蒙皮和骨骼，只在CPU审计加载时省去纹理；产品模型/材质未变。`motion-geometry.mjs` 使用实际手部蒙皮顶点的固定1/8采样、躯干皮肤横截面凸包（6mm内缩）、45mm双侧手臂胶囊间距和18mm对侧手臂内部风险检查。它们保守筛查可能接触，不能证明精确网格无碰撞；触发风险直接隔离，不将其判为错误手语，也不强行改成另一动作。

新门槛同时限制腕部残差P95≤0.4cm、峰值≤0.8cm，手指角残差P95≤1.5°、峰值≤6°，手臂角残差P95≤1.2°、峰值≤5°。不再允许只靠聚合P95掩盖局部大尖峰。骨骼数组、模型SHA256、源容器SHA256、资源字节和不批准标记继续受验证。

切换修复片段时先回归已检查的REST姿势、再进入下一个片段，合计240ms过渡，不跳过任何源帧。完整轨迹、帧间25%/50%/75%共47,277个样本、片段首尾与REST桥接以及任意采样姿态到REST的25%/50%/75%中间姿势均检查相同几何风险代理。本轮这些保留片段的检查未触发风险。
