# 第四阶段：动作库备份与安全批量导入

## 范围与验收条件

本轮承接覆盖分析和共享动作库，解决逐个导出动作容易遗漏、导入贡献包可能覆盖已有成果的问题。不新增未核验的手语词条，不修改骨骼轴、REST、模型、浮窗或预设。

| 条件       | 必须达到的行为                                                                          | 验证方式                             |
| ---------- | --------------------------------------------------------------------------------------- | ------------------------------------ |
| 整库备份   | 导出当前模型兼容的全部已保存动作，保留精确弧度和帧时长；不导出 ASR 密钥、字幕或浏览记录 | 单元测试与真实扩展下载               |
| 导入预检   | 文件选定后只显示清单，不写库；任一动作格式/模型不符则整包拒绝                           | 非法格式、模型、重复 ID 和超限测试   |
| 不覆盖     | 相同 ID 相同内容跳过；相同 ID 不同内容阻止整包写入，原数据不变                          | 状态及存储逐项比较                   |
| 不自动启用 | 新导入动作一律为草稿，不信任包内的启用或审核记录                                        | 翻译匹配、覆盖分析和人工确认流程测试 |
| 并发保护   | 预检后库发生变化必须重新预检；多页写库使用同一 Web Lock                                 | 并发及过期预检测试                   |
| 既有流程   | 编辑器、录制器、浮窗、覆盖分析保持可用                                                  | 重跑前三阶段浏览器检查               |

## 备份

修改前工作区快照标识：`phase4-20260920-160819`，维护者保存在仓库外的本地备份目录，不随源码发布。`project.tar.gz` 已通过 SHA-256 校验，包含前三阶段当时未提交的改动，不包含用户 `exports/`、依赖和测试临时产物。

项目文件备份不包含浏览器 `chrome.storage.local` 中的动作。两种备份用途不同，不能互相替代。

## 如何使用

先在扩展管理页重新加载构建后的 `signbridge/dist/`，关闭并重新打开旧工具页。必须从同一扩展的控制面板进入工具；单独打开 HTML 文件或另一个扩展 ID 不会读取原有动作库。

入口：**控制面板 → 姿势编辑器或录制工具 → 共享动作库 → 动作库备份 / 批量导入**。该区域默认折叠，不增加浮窗上的控制按钮。

### 备份当前动作库

1. 先用“保存草稿”保存需要保留的当前编辑内容。未保存的关节调整和录制帧不在整库备份中。
2. 展开备份区域，点击“备份全部已保存动作”。浏览器下载 `signbridge-日期.motion-pack.json`。
3. 保留项目版本和这个 JSON 文件。卸载扩展、清空扩展数据或换浏览器前，先确认备份可在相同模型的工具里通过预检。

备份包含已保存的草稿与已确认动作，而非内置词典或模型文件。无动作时明确报错；任何存储条目损坏/模型不匹配时，整库导出拒绝，不会静默省略。先排查提示，必要时用原有“下载统一 JSON”单独保存能读取的动作；不要为了通过检查直接删除旧记录。

### 导入或恢复动作包

1. 在备份区域的文件选择框选择动作包 JSON。**选文件只预检，不导入、不播放、不修改当前姿势。** 原有单动作导入框不用于动作包。
2. 查看新增、已存在和 ID 冲突数量，以及匹配文字冲突、无匹配文字、原导出启用标记等提示。
3. 有新动作且无 ID 冲突时，点击“确认导入新草稿”，再确认提示框。取消确认或取消文件不会写入动作库。
4. 新动作进入共享列表，全部是草稿。逐条“载入选中” → “预览当前动作” → 检查正面/侧面手形与轨迹 → “确认后用于翻译”。未确认前不能参与实时翻译或增加有效覆盖率。
5. 回到覆盖分析页重新分析真实语料，检查哪些词得到覆盖。覆盖率变化不代表手语语言质量已经通过审核。

恢复到空库时，即使备份标记某动作原来已启用，也需要重新预览、确认。导入到已有库时，相同动作的本地启用状态保持原样。该功能是“不覆盖的合并导入”，不是清空本地库后还原整个浏览器状态。

## 冲突与异常处理

| 提示 / 场景                               | 行为                                               | 建议                                                            |
| ----------------------------------------- | -------------------------------------------------- | --------------------------------------------------------------- |
| 相同 ID、相同内容                         | 跳过，不覆盖本地启用/停用状态                      | 无需重复导入                                                    |
| 相同 ID、内容不同或对应本地记录损坏       | 整包拒绝，连无冲突的新条目也不写入                 | 保留双方备份，人工比较；需要独立副本时用原有单动作导入生成新 ID |
| 匹配文字与内置/本地/包内动作冲突          | 显示警告，允许先导入草稿；启用仍受别名冲突检查约束 | 结合语义整理匹配文字，不用不同 ID 绕过启用检查                  |
| 没有匹配文字                              | 作为姿势素材保存，不可用于文字翻译                 | 确认语义后再填写匹配文字                                        |
| 预检后另一工具页修改动作库                | 清除过期结果，导入按钮禁用；锁内也会复查           | 点击“重新预检”                                                  |
| JSON、UTF-8、版本、模型、帧数据或容量不符 | 拒绝整包，不改变当前编辑内容                       | 使用本工具导出的 UTF-8 JSON，勿手工改绑定字符串                 |
| 浏览器存储不足 / 写入失败                 | 显示失败，不逐条循环写入、不自动重试或启用         | 保留文件，检查空间与已有备份后重新预检                          |
| 缺少 Web Locks 支持                       | 拒绝批量写入                                       | 使用受支持的 Chromium 扩展页面                                  |
| 关闭/刷新页面                             | 丢弃待导入文件与预检结果，不自动恢复或写库         | 需要导入时重新选择文件                                          |

匹配文字比较复用翻译分词规则，例如大小写和分隔符差异不保证它们是两个独立别名。草稿之间的同名警告不等于所有草稿必须删掉，只是提醒在正式启用前作选择。

## 数据格式与限制

```text
signbridge-motion-pack v1
  createdAt: 导出时间
  motions[]
    asset: 完整的 signbridge-motion v1
    wasEnabled: 导出时启用状态（仅作提示）
```

- 每包最多 500 个动作，UTF-8 文件最多 8 MiB；规范化后按下载格式生成的 JSON 也不能超限。
- 每个动作最多 2 MiB、240 帧、120 秒；单帧 0.05–10 秒。角度保留精确弧度，不取整、不转轴，单位与模型绑定沿用第二阶段规则。
- 一个包内不能有重复 ID，即使重复内容完全相同也拒绝。
- `wasEnabled` 不等于审核证明；未知字段和外来审核记录不会导入。内置词条、GLB、材质、浮窗配置、ASR 密钥、字幕记录不在动作包中。
- 没有自动分包、云同步、跨模型重定向或批量启用。整库超过容量限制时应先单独备份动作，不会自动截断后宣称备份完成。
- 动作名称、匹配文字、标签和模型骨骼绑定可能包含私人信息；分享 JSON 前检查内容。本功能不主动上传文件，但不负责浏览器下载目录的其它同步软件。
- 名称按纯文本显示，不执行文件中的 HTML/脚本；文件不要求也不包含可执行代码。

绑定校验不是完整 GLB/蒙皮权重指纹，动作确认也不是手语专业认证。收录第三方动作前需要核实来源、授权与表达质量。

## 实现与复测

实现入口：

- `signbridge/src/avatar/motion-pack.js`：格式、大小、ID、模型和别名预检。
- `signbridge/src/avatar/motion-library.js`：整库导出、快照检查、同锁批量草稿写入。
- `signbridge/src/avatar/motion-pack-ui.js`：两个工具共用的折叠式入口、确认和取消、过期结果处理。
- `signbridge/tests/motion-pack.test.mjs`：精度、校验、冲突、并发、存储失败和多语言键测试。
- `signbridge/tests/browser-phase4.mjs`：真实扩展、真实模型、实际文件下载与导入流程。

```bash
cd signbridge
npm run verify

SIGNBRIDGE_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
SIGNBRIDGE_CHROMIUM_PATH=/absolute/path/to/chromium \
node tests/browser-phase4.mjs
```

浏览器检查在临时配置中创建测试动作，不改日常浏览器的数据。检查整库下载、预检不写库、取消、精度往返、确认门槛、重复导入、冲突、跨页过期、非法文件及延迟读取取消；结果与截图在 `signbridge/test-results/phase4-browser/`。还需用相同环境重跑 `browser-phase1.mjs`、`browser-phase2.mjs` 和 `browser-phase3.mjs`，防止破坏浮窗、字幕与共享库/覆盖分析流程。

测试用任意匹配文字验证数据链路，不把测试姿势当作正确的 CSL 手语。无外部请求的本地测试不能替代所有视频网站兼容性、真实 ASR 识别或手语使用者验收。
