# 第三阶段：用真实语料驱动词库扩展

## 目标与不做的事情

第一阶段稳定输入/播放生命周期，第二阶段统一动作数据与人工确认流程。本阶段回答“应该优先补哪些词、补完有没有生效”，而不是凭数量批量生成未验证的手语。

- 保持 52 个内置词条、172 个查找别名、16 个单字回退不变。
- 不修改模型、骨骼轴向、REST、预设、浮窗尺寸/高度和鼠标控制参数。
- 不把词库命中率描述为手语准确率，不替代 CSL 语法重排、非手控特征或专业审核。
- 不监听或自动保存浏览记录、字幕、声音转写，不调用云端服务。

## 使用方法

1. 构建后，在扩展管理页重新加载当前扩展。关闭旧工具页，从控制面板点击新增的 **词库覆盖分析**。
2. 粘贴文字，每行作为一段；或者导入 UTF-8 编码的 TXT、SRT、VTT 文件。粘贴字幕时，手动选择对应格式。
3. 点击 **分析当前词库**。首次分析读取当前 GLB，以核验自定义动作是否与实际运行模型相容；不创建可见模型或动画循环。
4. 查看覆盖统计、未覆盖词次数、出现段数和最多三个例句段号。展开逐段明细查看命中动作 ID、未覆盖词、跳过词及播放上限后的剩余文字。
5. 结合上下文决定制作单词还是词组。点击某个词旁的 **姿势编辑器** 或 **录制工具**，新页面只预填名称和匹配文字。当前姿势不代表该词，须自行制作并核验。
6. 保存草稿 → 预览 → 人工检查 → 确认启用，沿用第二阶段门槛。回到分析页，点击分析；新动作真正生效后才计入覆盖。
7. 需要保留结果时主动导出 JSON。默认只包含统计、未覆盖词和自定义动作 ID；勾选包含原文后才导出逐段明细。

材料仅保存在当前页面内存，关闭/刷新页面后不保留。动作工具的新页面 URL fragment 包含所选词，因此浏览器会话/历史记录可能保留该词；不要用敏感词做工具跳转。报告即使不含原文，也仍包含未覆盖词，分享前务必检查。

## 指标如何读

```
词库覆盖率 = 命中的分词数 / (命中的分词数 + 未覆盖的分词数)
```

使用与运行时相同的标准化、分词和最长匹配。跳过的虚词与标点不进入分母；没有待翻译词时显示“不适用”，不伪造 100%。一个多词别名按实际包含的分词数计入，不按动作数量计入。

例如两段 `你好 quasar quasar` / `谢谢 quasar`：内置词命中 2 个分词，未覆盖 3 个分词，覆盖率 40%。`quasar` 出现 3 次、分布在 2 段。为测试该匹配文字启用一个自定义动作后，词库覆盖率可达 100%，但这**不能证明该动作正确表达 quasar**。此例仅说明统计口径，不是手语示范。

- **全段词库覆盖**：分析完整一段，不因为 12 个动作上限停止统计。
- **实时播放截断**：另按运行时默认 12 个动作计算，标出可能未播放的剩余文本。
- **队列丢弃与播放耗时**：此页不模拟视频的字幕到达节奏，也不预测两段队列溢出/6 秒过期；不能据此保证实际完整播放。
- **跳过词**：只是现行转换器的规则，不意味着这些词在所有 CSL 句子中都可省略。
- **未覆盖词**：是分词结果，不是自动审核通过的补词清单。结合语境、否定、指代及完整词组再决定是否制作。

重复字幕条目按出现次数统计，不自动去重。带有滚动累计字幕的文件可能夸大某些词频，导入前可去重整理。SRT/VTT 时间戳只用于解析验证和分隔条目，不用于本页同步播放。没有匹配的标点段不影响分母。

## 与当前词库保持一致

- 从共享本地动作库读取，校验模型骨骼/REST、结构、精确确认记录及别名冲突。
- 未保存、草稿、未确认、停用、失效或模型不匹配的动作不计入有效覆盖。
- 读取模型或动作库失败时明确报错，不输出“看似成功但漏掉自定义动作”的结果。
- 输入、格式或动作库变化时，旧结果隐藏、旧导出禁用，必须重新分析。
- 工具跳转不覆盖旧动作、不自动保存、不绕过人工确认。词过长时禁用跳转，应人工重新判断词组。

## 文件与安全限制

| 项目 | 上限 / 行为 |
| --- | --- |
| 输入文件 | 256 KiB；UTF-8（可带 BOM） |
| 文本 | 50,000 个 JavaScript 字符单位 |
| 区间 | 1,000 段，每段最多 2,000 字符单位 |
| 页面展示 | 前 100 个未覆盖词、前 200 段；总计包括全量数据 |
| JSON 导出 | 全量统计，原文/逐段明细须额外勾选 |
| 字幕解析 | 支持常用 SRT/WebVTT 文本、时间轴、标签、注释/样式块；非完整格式修复器 |

文件过大、不支持的扩展名、无效 UTF-8 会报错并保留原输入。字幕缺时间轴、缺必要空行、结束不晚于开始或 VTT 缺文件头会拒绝分析，避免把时间码或错误片段计入词频。源文本通过 `textContent` 显示，不执行 HTML 或脚本；导出用 JSON，不使用可能触发表格公式的 CSV。

## 开发与复测

主要入口：

- `signbridge/src/tools/coverage.html` / `coverage.js` / `coverage.css`
- `signbridge/src/avatar/coverage-analysis.js`
- `signbridge/src/avatar/motion-library-ui.js`：仅增加元数据预填，不改骨骼数据或保存规则。
- 构建输出 `signbridge/dist/tools/coverage.html`，入口在插件控制面板。

运行：

```bash
cd signbridge
npm run verify
SIGNBRIDGE_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
SIGNBRIDGE_CHROMIUM_PATH=/absolute/path/to/chromium \
node tests/browser-phase3.mjs
```

第三阶段单元测试覆盖文本/字幕解析、异常和边界、统计分母、多词别名、运行时一致性、截断、隐私导出与多语言键。隔离浏览器测试加载构建后的真实扩展和 GLB，检查入口、模型失败后重试、草稿不生效、确认后生效、停用、编辑器与录制器预填、导入导出、安全渲染及无外部请求。测试只在临时浏览器配置中创建数据，不改用户动作库。

另外重新运行 `tests/browser-phase1.mjs` 和 `tests/browser-phase2.mjs`，防止新入口/共享面板破坏既有浮窗、字幕与动作制作链路。结果存于各 `test-results/phase*-browser/`（不提交）。

这些验证不等于全网站兼容、生产云端 ASR 验收或手语语言学认证，也不宣称项目完全无错误。
