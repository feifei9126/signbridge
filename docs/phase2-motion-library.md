# 第二阶段：共享动作库

## 这一阶段解决什么

过去，编辑器、录制器和浮窗之间存在度数/弧度、绝对旋转/REST 增量、`pose`/`value` 字段的差异。即使编辑器中调对了，复制到另一处仍可能解释错误。这一阶段统一数据和播放器，不再靠试着反转某个轴来接通动作。

本阶段不更换模型，不重调已确认的骨骼预设，不改变浮窗的尺寸、位置和鼠标控制参数，也不新增未经人工验证的手语词条。原有 52 个内置词条、172 个别名和 16 个单字回退保持不变。

## 从哪里打开

1. 构建后，在 Chrome 扩展管理中重新加载现有扩展。
2. 关闭旧工具标签页，从扩展控制面板重新打开“姿势编辑器”或“录制工具”。不要继续使用旧 bundle 的标签页。
3. 等待模型及“共享动作库”面板出现。姿势编辑器做单帧，录制器做多帧。

两个页面与浮窗使用同一扩展的 `chrome.storage.local`。不需要把文件复制进项目，也不需要为每次保存重新构建；已确认动作会被打开的浮窗自动读取。独立 localhost 静态页没有这份扩展存储，不能与扩展动作库自动互通。

## 制作并使用一个动作

### 单帧姿势

1. 用原有预设或骨骼滑块摆好姿势。
2. 填写**动作名称**（供自己识别）、**匹配文字**（输入什么时播放）、可选分类标签。多段匹配文字用逗号分隔。
3. 点击**保存草稿**。草稿不会参与翻译。匹配文字可留空，作为待组合的姿势素材保存。
4. 点击**预览当前动作**，从正面和侧面检查手掌、手指、肘部、穿模和表达含义。
5. 点击**确认后用于翻译**，阅读确认框后启用。
6. 回到视频页，在扩展控制面板输入刚填的匹配文字，验证浮窗动作；字幕或声音转写包含该匹配词组时也能调用它。

匹配文字不能与内置词或其他已启用动作重复；比较使用与翻译相同的分词规则，不靠大小写、空格或连字符绕过冲突。确认时提示冲突，应修改文字或停用冲突的自定义条目，而不是修改内置词条。

### 多帧动作

1. 在录制器中摆好第一帧，设置“关键帧时长”，点击添加关键帧。
2. 继续摆下一帧并添加。可载入编辑器保存的单帧姿势作为起点。
3. 修改已有帧：点击时间线中的帧 → 调骨骼或时长 → **更新选中帧**。仅拖动滑块不会自动覆盖时间线中已有的帧。
4. 自动录制按 0.3 秒采样；手动添加与更新使用时长输入框。单帧 0.05–10 秒，最多 240 帧，总时长最多 120 秒。
5. 填名称、匹配文字、标签，然后依次保存草稿、预览、确认。预览采用与浮窗一致的过渡逻辑。

帧时长包括到达姿势的插值与随后的停留，并不表示全程等速运动。需要持续轨迹时应设置多个姿势点，而不是只增加某一帧时长。

## 修改、停用与备份

- 从列表选择动作，再点“载入选中”。编辑器拒绝载入多帧动作，请用录制器打开，避免丢失后续帧。
- “新建副本”保留当前姿势/帧，但创建新 ID、清空元数据；不会覆盖之前的动作。
- 每次“保存草稿”都撤销旧确认；改过的动作须重新预览、确认才能恢复翻译。只在页面上修改但尚未保存，不会改动已存储的版本。
- “停用选中动作”保留素材，但不再参与翻译。有效翻译目录变化时浮窗取消旧播放和待播队列，防止继续使用刚停用的动作；普通未启用草稿的保存不打断播放。
- “下载统一 JSON”下载当前内容，不自动保存或启用。导入也只是载入一个新 ID 的副本，需要手动保存；导入文件不能继承启用资格。
- 动作库只在当前浏览器用户配置和扩展 ID 中共享，不使用 Chrome Sync。卸载扩展、清除扩展数据或更换扩展 ID 前请下载备份。

## 旧数据如何迁移

不要直接粘贴旧 JavaScript 执行。导入器只读取 JSON，且必须明确选择格式：

| 入口/格式                   | 接受的数据                                        | 转换方式                             |
| --------------------------- | ------------------------------------------------- | ------------------------------------ |
| 统一格式                    | `signbridge-motion` v1 完整文件                   | 校验后直接使用弧度增量               |
| 旧编辑器 delta · 度数       | 仅姿势对象，如 `{"head":{"x":-43.9,"y":0,"z":0}}` | 度数转弧度，映射标准骨名             |
| 旧录制器 frames.pose · 度数 | `{"frames":[{"pose":{...},"duration":0.8}]}`      | 每帧度数转弧度，`pose` 转为 `value`  |
| 旧编辑器绝对旋转 · 弧度     | 仅姿势对象                                        | 减去当前模型对应骨骼的 REST 旋转     |
| 迁移本页旧动作库            | 本扩展页 localStorage 的 `sb_gestures`            | 按历史度数格式生成新草稿；原数据保留 |

旧文件没有模型绑定，必须确认来自当前模型且单位相符。迁移后逐个检查，不能认为“转换成功”就代表手语正确。重复迁移会生成副本，不删除原库。其它浏览器或 localhost 的旧 localStorage 不会自动读取。

## 数据契约与安全边界

需要一次备份全部已保存动作，或接收多动作贡献文件时，使用共享面板中的“动作库备份 / 批量导入”。它与此处的单动作 JSON 导入不同：保留稳定 ID、先预检且不覆盖旧动作。具体恢复和冲突处理见[第四阶段指南](phase4-motion-packs.md)。

- `type: "signbridge-motion"`，`version: 1`，`space: "humanoid-local-v1"`，`unit: "radians"`。
- `frames` 为 `{ value: { 标准骨名: { x, y, z } }, duration }`，旋转是相对模型 REST 的本地增量，时长单位为秒。未提供的骨骼回到 REST。
- 录制器的骨骼滑块显示绝对本地弧度；捕获时统一转换为增量。编辑器的 `dg(...)` 预设接受度数只是编写便利，不改变导出单位。
- 完整资产带 `id`、`gloss`、`texts`、`tags` 和 `rig`。`rig` 比较 profile、骨骼/父节点名、REST 旋转以及局部位置/缩放；不兼容即拒绝，不强行套用。
- 文件上限 2 MiB，最多 240 帧，每轴必须是有限数值且绝对值不超过 2π；版本、单位、骨名、模型和时长不合法均拒绝。导入失败不替换当前姿势或时间线。
- 保存采用每个动作单独存储键。确认记录绑定规范化后的完整数据，存储键顺序变化不会改变批准状态；跨工具页写入通过同一 Web Lock 排队。
- 损坏条目会被跳过并显示提示，原始记录不自动删除。动作名称用文本节点显示，不作为 HTML 执行。

骨骼/REST 绑定不是完整 GLB 或蒙皮权重指纹；两个文件即使绑定相同也可能存在视觉差异。通过校验和人工点击确认，都不等于获得专业中国手语认证。动作含义、语法、手部细节与非手控特征仍需手语使用者验收。

## 常见排查

| 情况                   | 先检查                                                                                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 浮窗不播放新动作       | 是否保存、预览、确认；是否有匹配文字；输入是否命中该词组                                                                    |
| 提示重新保存/预览      | 姿势、帧或元数据是否刚改过；另一工具页是否保存了新版本                                                                      |
| 导入提示模型不一致     | 是否来自相同 profile 和 REST；不要编辑绑定字符串绕过校验                                                                    |
| 预览时手形不对         | 检查原预设与数据单位、从侧面检查；不要全局反转词库角度                                                                      |
| 工具里没有共享动作库   | 是否重新加载扩展并关闭、重开旧工具页；是否仍打开静态页                                                                      |
| 修改后浮窗仍播放旧内容 | 查看 `[SB] Motion library:` 与 `[SB] Translation coverage:`，核对已启用数量与 `motionIds`；确认浏览器用户配置和扩展 ID 一致 |

## 验证方法

```bash
cd signbridge
npm run verify

# 已准备独立 Playwright 和 Chromium 时执行：
SIGNBRIDGE_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
SIGNBRIDGE_CHROMIUM_PATH=/absolute/path/to/chromium \
node tests/browser-phase2.mjs
```

浏览器脚本在临时用户配置中加载 `dist/`，验证编辑器保存、草稿不翻译、确认后热加载、录制器往返、多帧播放、非法导入、历史迁移和保存撤销确认。报告与截图输出至 `signbridge/test-results/phase2-browser/`。第一阶段回归脚本为 `tests/browser-phase1.mjs`。

自动测试验证数据、流程和可见交互，不替代对真实手语词义的人工验收，也不能证明所有视频网站和所有模型均兼容。本阶段没有接入 glTF AnimationClip 导入、AI 语法翻译或批量自动生成标准手语。
