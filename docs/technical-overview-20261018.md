# SignBridge 技术总览与训练验证记录

**汇报日期：2026-10-18｜对象：中国手语（CSL）｜用途：研究与演示**

> **一句话结论：** SignBridge 已将字幕／文本接入既有中文手语动作库，并完成 SMPL-X 视频拟合、动作编码重建和一个受限中文语义解析实验；当前仍不是开放域中国手语翻译模型。词典匹配、动作重建和中文语义解析是三个不同能力，不能互相替代。

## 2. 词条到底有多少

手写内置动作词典 `signbridge/src/avatar/sign-language-data.js` 当前统计：

- **52 个 `SIGNS` 动作概念对象**：每条含匹配文本、标签和一段或多段手臂／手指姿势帧。
- **177 个声明的 `texts` 别名项，去重后 172 个查找键**：同义说法、变体和大小写规范化后的搜索入口；不是 172 个独立 gloss，更不是 172 个专家核准的 CSL 词条。
- **16 个 `CHARS` 单字回退姿势**：也不是通过语言模型训练得到的字形转换。
- **中文语义研究模型**有 32 种谓词表面形式与 11 个语义角色标签；这些角色词汇不等同于符号词典或 32 个手语动作。
- 其他 motion assets 统计口径不同：T08 有 14 个实际 token 解码参考片段；另有 3 个 T08 重建候选句；一份实验性索引有 83 条拟合动作。六批审计的 112 条 runtime 记录属于分来源／历史使用范围，且与这些索引重叠，**不能把这些数字相加当作句子总数**。

本地当前目录另可按 `buildDemoPhraseCatalog` 复算为 **153 个混合目录项＝14参考＋3候选＋83实验＋53预设词库组合**；52个内置字典动作由界面另列。该目录项数不等于独立句子数、训练集句数或模型的语言能力。

词典是“可检索动作覆盖”，不是连续手语句子的语法模型。匹配到同义词也不保证其语境语义和中国手语表达正确。

## 3. 训练模型与发布记录

### T01–T10 动作编码研究轮次

这些轮次训练的是 133 维上身／手部动作表示上的 SOKE/VQ tokenizer 重建实验。训练目标是让动作编码后能重建输入动作特征，不是让模型理解汉语并生成 CSL。

| 轮次 |                      数据范围 | 步数 |   记录中的最佳训练目标 | 证据与结论                                           |
| ---- | ----------------------------: | ---: | ---------------------: | ---------------------------------------------------- |
| T01  |                    2段／384帧 |  500 |     window MSE 0.02085 | checkpoint SHA-256 本地核验                          |
| T02  |                    2段／384帧 |  500 |     window MSE 0.01473 | 独立保存权重；重载复核                               |
| T03  |          2段／384帧，融合特征 | 1000 |     window MSE 0.00509 | 新权重；目标口径与前轮不同                           |
| T04  |        2段／384帧，保守时序版 | 1000 |     window MSE 0.00506 | 新权重；训练损失不能单独证明动作更好                 |
| T05  |   2段／384帧，mask 输入修正版 | 1000 |     window MSE 0.00570 | mask／特征范围改变，不能直接排名                     |
| T06  | 医院动作训练 → 问候留来源诊断 | 1000 |     window MSE 0.00177 | 按来源折分实验；不是真实 signer 独立证明             |
| T07  | 问候动作训练 → 医院留来源诊断 | 1000 |     window MSE 0.00071 | 按来源折分实验；不是 CSL 准确率                      |
| T08  |              其余14段／2732帧 | 1000 | normalized MSE 0.08484 | 保留的研究基线；checkpoint SHA-256 核验              |
| T09  |    相同14段，自动筛查 mask v1 | 1000 | normalized MSE 0.11342 | 独立候选权重；没有整体替换 T08                       |
| T10  |    相同14段，歧义手别 mask v2 | 1000 | normalized MSE 0.13554 | 后续从完整提取包恢复并核验 SHA；没有因损失变化而晋升 |

9份权重在 2026-10-10 的冻结注册表可本地核验；T10 当时只保留远端终端记录。2026-10-15 的去重归档恢复了 T10 完整权重，SHA-256 为 `9d834e8fe0f13e39499e7640085d89ff6bc8cbd3bb5b7813481047bfc64f4a54`。T01–T10 各轮权重摘要不同；T08/T09/T10 实际使用的是同一14段、2732帧的特征内容，只是 mask 与训练版本不同。这不代表三份独立数据集。

总更新步数可记作10轮各自训练步数的合计，但它不是帧数、独立样本数或单一权重连续训练步数。不同轮次的归一化、mask、样本／目标函数口径变化，MSE不能跨全部轮次简单排序。

## 6. 骨骼驱动与动作格式

### 手写动作

`pose-engine.js` 的 `deg()`、`frm()` 和片段构建 API 生成每帧关节旋转及持续时间。`sign-language-data.js` 提供肩、上臂、前臂、手腕和手指关节旋转；手形 primitive 将拳、掌、指等参数写入各指骨。翻译器按完整词项／别名查找，匹配到的片段依文本顺序拼接；不认识的文本不会被模型翻译。

### 拟合动作

视频帧经 SMPLer-X 得到 SMPL-X 参数。导出特征通过原生字段映射为每帧133维：上身30、左手45、右手45、下颌3、面部表达10。演示文件中的有效姿态以55个关节、每关节3个轴角值表示，并绑定 rest joints 与关节父子表。

Three.js retargeter 将轴角转为四元数，沿父子层级累计 source world rotations；读取目标 GLB 的骨架 rest pose、骨段方向和掌面法向，计算源／目标坐标对齐修正，再映射到40条目标骨骼链接（颈、头、肩、上下臂、手和30节手指）。播放时按帧插值并可应用独立的 display-only 稳定器。

当前重建 Demo 只映射上身和手，root／下肢／部分躯干保持 rest pose；SMPL-X jaw 的轴系未对齐时让 avatar 面部保持 rest。**这不是完整全身动作重定向，更未建模 CSL 非手部语法。**

## 7. 当前中文语义研究模型

2026-10-17 的 `learned-roles-v3` 是 NumPy 实现的平均结构感知机，以字符上下文特征和 BIO 转移做中文片段角色标注。11类角色：施事、谓词、受事、目标、时间、否定、情态、疑问、体貌、请求、程度。模型表有104个训练支持字符、32种谓词表面形式和3687个稀疏字符特征。它不输出 calibrated confidence，也不加载视频或动作。

| 数据切分   |  数量 | 完全匹配 | 注释                           |
| ---------- | ----: | -------: | ------------------------------ |
| Train      | 6,355 |        — | 助手合成中文标签               |
| Validation |   881 |  881/881 | 按施事／谓词／对象组留出       |
| Test       |   764 |  764/764 | 合成数据同域留出               |
| Challenge  |    34 |    34/34 | 17解析、17拒绝；由同开发者构造 |

这些100%只反映受限合成语料；不是现实语言理解准确率，更不是 CSL 翻译准确率。挑战集上的 abstention 本身计为正确结果。当前薄客户端只显示语义角色并要求 CSL 对齐复核；没有将模型输出接到词典自动播放或手语生成。

## 9. 从 Demo 到 CSL 理解模型的路线

1. **语言标注**：对原视频逐词／短语核准 Gloss、时间区间、句界、语境与否定／疑问范围；独立复核双语字幕与教材指令是否一致。
2. **动作审阅**：核准两手、身体、面部／头部非手控特征、空间指代、镜像／解剖侧别、signer及录制条件；不确定和缺失保持缺失。
3. **数据划分**：按视频来源、课程片段和 signer 防泄漏划分 train／validation／test；对每个可用序列锁定 provenance/hash。
4. **基线生成**：训练 Chinese semantic parser → CSL Gloss / construction planner → motion unit retrieval/sequence generation。动作检索只是可靠基线；不应拿它冒充新生成模型。
5. **生成模型候选**：文本语义编码器 + Gloss/结构中间表示 + 离散动作 tokenizer + 时序 Transformer/扩散解码器；对双手和非手控特征分层建模，并用骨骼约束、碰撞/时序质量损失和拒答机制控制输出。先研究与验证，不直接部署。
6. **验收**：语义保真、词／短语边界、双手轨迹、空间和非手部表达由 CSL 使用者/专家评审；同时测 held-out signer/source、覆盖率、缺失率、重建质量、流畅度、延迟和错误拒绝。只有质量 gate 通过后再开 `training_ready` 和 Demo 生成路径。
